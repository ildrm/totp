# Threat model

Assets are consumer OTP seeds and metadata, vault/recovery keys, correct counters and revisions, cloud passkey sessions, verifier seeds/API keys, availability, and recovery data. Boundaries are the browser UI/worker/storage, untrusted network and sync relay, passkey authenticator, consumer database, separate verifier/KMS, and deployment/build pipeline.

Likelihood and impact below are qualitative for an Internet-hosted authenticator, not measured probabilities. Control claims refer to implementation and tests; independent validation is still required.

## Security claims excluded

Still does not promise protection against a compromised unlocked browser/OS, guaranteed JavaScript zeroization, phishing resistance for TOTP/HOTP, trusted global relay freshness on a new device, cryptographic read-only access for someone holding a shared key, retroactive deletion from a revoked member, or automatic recovery without saved key material and data. No FIPS certification or independent audit is claimed.

The random 96-bit GCM nonce suite requires a conservative per-key encryption budget. The recommended 2^24 upper budget is operational guidance; a trustworthy distributed aggregate counter is not enforced. High-volume deployments must add enforceable epoch/write budgets or review a misuse-resistant/new suite before that scale.
