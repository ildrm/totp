# Data and retention inventory

| Data                                                                 | Location                                                           | Protection / purpose                                                         | Retention                                                                                  |
| -------------------------------------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Seeds, account labels, notes, tags, aliases, folder, usage, settings | Browser IndexedDB; optional relay ciphertext                       | AES-GCM; decrypted only by an unlocked worker                                | Until local deletion / vault or cloud account deletion; external backups remain            |
| Wrapped vault keys, KDF costs and salt, key/vault IDs                | Browser IndexedDB; encrypted backups                               | Public parameters plus authenticated encrypted key wraps                     | Until vault deletion; old backups retain old wraps                                         |
| Unlocked vault key and plaintext records                             | Dedicated worker memory; necessary visible metadata/codes in React | Non-extractable key objects, isolated lifecycle, best-effort buffer clearing | Worker terminated on lock; JavaScript GC cannot guarantee forensic erasure                 |
| Theme and language                                                   | localStorage `still.preferences`                                   | Non-sensitive display preferences only                                       | Until preferences/site data cleared                                                        |
| App shell and hashed static assets                                   | Service-worker Cache Storage                                       | Fixed build allowlist; no `/api/`, query responses, secrets or ciphertext    | Build cache replaced on controlled update / site data deletion                             |
| Opaque user/device/vault IDs and shared roles                        | PostgreSQL consumer schema                                         | Authorization and ciphertext routing                                         | Until applicable account/device/vault deletion                                             |
| Public passkey ID, key, counter, transports, backup flags            | PostgreSQL                                                         | WebAuthn authentication metadata; no private key                             | Until passkey/account deletion                                                             |
| Session and challenge token hashes                                   | PostgreSQL                                                         | Opaque secrets in HttpOnly SameSite cookies; raw tokens not stored           | Challenge 3 minutes; session 7-day maximum and 1-hour idle; cleanup every 10 minutes       |
| HMAC rate-limit buckets                                              | PostgreSQL                                                         | Rate control; raw IP is not stored in the bucket                             | Per-window expiry; cleanup every 10 minutes                                                |
| Security event type, timestamp, opaque user/device ID                | PostgreSQL                                                         | Account-visible security history; no request body/seed/code                  | 90 days; account deletion cascades; periodic cleanup                                       |
| Pairing public keys/context and encrypted key envelope               | PostgreSQL                                                         | Short-lived device transfer                                                  | Three-minute expiry, one-time approval; periodic cleanup                                   |
| Sync operation IDs, revision/base, tombstone, ciphertext/proof       | PostgreSQL                                                         | Conflict resolution and replay detection                                     | History retained until vault deletion; rotation filters old-key history from current pulls |
| Verifier application name and credential parameters                  | PostgreSQL separate verifier schema                                | Developer administration                                                     | Until credential/application/account deletion                                              |
| Verifier seed                                                        | Separate schema encrypted envelope                                 | AWS KMS production, app/credential encryption context; service can decrypt   | Until credential deletion; KMS and database backups governed by operator policy            |
| Verifier subject identifier                                          | Hashed application + UUID                                          | Bind factors to an opaque subject, without email/username                    | Until credential deletion                                                                  |
| Verifier API keys and recovery codes                                 | Only hashes in PostgreSQL                                          | High entropy bearer verification, scope/expiry, one-time code consumption    | API keys maximum 90 days/revocation; recovery until consumed/replaced/credential deletion  |

No analytics, advertisements, remote issuer images, remote fonts, password reset email, or seed telemetry are implemented. Framework telemetry is disabled in build/development commands. Reverse proxies still process IP addresses, and hosting providers, DNS, TLS, operating systems, passkey sync providers, and browser extensions have their own data policies. Deployment defaults do not enable access logs.

Support artifacts must contain only software versions, generic error categories, and synthetic fixture reproduction steps. Never collect browser storage dumps, vault exports, recovery kits, provisioning URIs, API keys, request bodies, or authentication codes from users. Automated test artifacts are generated from synthetic data; do not reuse the test browser profile for real accounts.

Deleting a cloud account deletes that account's owned database rows through defined cascades. It does not securely erase copies in database backups, prior shared members' devices, external exports, or KMS audit systems. Publish actual operator retention and deletion schedules before offering a hosted service.
